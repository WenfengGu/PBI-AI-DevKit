# PBI AI DevKit -- 开发立项计划

> Power BI AI Development Toolkit for Claude Code

> 项目编号：PBI-MCP-2026-001 | 版本：1.0 | 日期：2026-07

---

## 1. 项目背景

### 1.1 业务痛点

团队以 Claude Code 为日常 AI 工具，但在 Power BI 开发中面临以下问题：

- **PBIX 文件读取困难** -- 核心模型数据为压缩二进制格式。虽然 Claude 可以逐层解压、逐文件读取，但需要反复对话、消耗大量 Token，效率极低且容易遗漏
- **手工排查效率低** -- 列名变更时需逐个打开 Measure 检查，大型模型中耗时且易遗漏
- **批量修改无工具** -- Power BI Desktop 不支持跨 Measure 搜索替换，第三方工具需要额外安装和学习
- **ChatGPT/Copilot 的官方 Power BI MCP server 无法在 Claude 中使用** -- 这些能力绑定在各自生态中，团队使用的 Claude Code 无法直接调用

### 1.2 市场现状

| 方案 | 能力 | 局限 |
|------|------|------|
| 官方 Power BI MCP (Preview) | 读写模型 | 需 Node.js 环境，认证流程复杂 |
| 社区 MCP 方案 | 仅读取 | 不支持修改 Measure |
| ChatGPT/Copilot | 可通过官方集成读写模型 | 绑定在各自生态，Claude 用户无法使用 |

**结论：** Claude Code 生态中缺少可读写的 Power BI MCP，需要自建方案填补空白。

---

## 2. 项目目标

构建一个 **Claude Code 插件**，通过 MCP 协议 + Skill 指令，使 Claude 具备以下能力：

- 连接本地 Power BI Desktop，快速获取模型完整信息
- 读取模型元数据（表、Measure、DAX 表达式、关系）
- 搜索和修改 Measure 定义，支持批量操作
- 审计 Power Query 代码，发现优化机会
- 执行业务分析查询，生成结构化报告（如：一句话拉取月度销售快照、渠道对比、客户分层、同比环比等，自动合成多维度洞察）
- 零配置部署，非技术人员可一键完成

---

## 3. 技术方案（概要）

### 3.1 核心思路

借用 Power BI Desktop 自带的客户端库，通过 Python 桥接调用，直接连接本地引擎。全程本地运行，无需网络、无需认证。

### 3.2 架构概览

```
Claude Code -> MCP 协议 -> Python Server -> PBI Desktop 引擎 -> 本地模型
```

### 3.3 关键技术点

| 组件 | 方案 |
|------|------|
| 开发语言 | Python |
| .NET 桥接 | 开源桥接库 |
| 模型读取 | 官方数据库驱动接口 |
| 模型修改 | 官方对象模型接口 |
| 实例发现 | 自动检测本地进程及端口 |
| 部署 | 一键脚本，自动检测环境 |

## 4. 阶段性开发计划

项目按由易到难分为 5 个阶段，每阶段产出可独立交付的增量功能。

### Phase 1: 基础连接与读取

**难度：★☆☆☆☆ | 预估工时：4h**

> 打通 Python -> Power BI 的数据通道，实现基本的模型读取能力。

核心任务：
- 实现 MCP 通信协议
- 自动发现本地 Power BI 运行实例
- 读取模型基础信息（表、Measure、列、关系）
- 支持 DAX 查询执行
- 支持 DAX 表达式全文搜索

**预计交付：** 一组基础读取工具，可获取任意本地模型的完整元数据。

### Phase 2: 模型修改与 Power Query

**难度：★★☆☆☆ | 预估工时：6h**

> 实现 Measure 修改能力和 Power Query 代码审计。

核心任务：
- Measure 表达式文本替换，支持批量操作
- DAX 语法预校验
- Power Query M 代码的读取与分析
- 查询优化建议（折叠检查、复杂度评估）
- 模型快照导出

**预计交付：** 扩展至读写工具集，新增 Power Query 审计能力。

### Phase 3: 高级读写与事务

**难度：★★★☆☆ | 预估工时：8h**

> 实现完整的模型创建/删除能力和事务批处理，以及业务洞察分析。

核心任务：
- Measure 的创建和删除
- 计算表、列、关系的创建
- 多操作事务化执行，失败自动回滚
- 模型拓扑关系图谱
- 多维度业务分析查询（时间对比、渠道分析、客户分层等）
- 结构化分析报告生成（基于模型探索结果，自动合成多维度交叉洞察）

**预计交付：** 完整的模型读写能力，事务安全保障，以及一键式业务洞察分析。

### Phase 4: 智能分析与代码质量

**难度：★★★★☆ | 预估工时：8h**

> 对标业界主流工具的代码分析功能，实现 DAX 静态分析。

核心任务：
- DAX 表达式解析与规则检查
- 覆盖性能、可维护性、正确性、命名规范等维度
- Measure 间依赖关系追踪
- 修改影响范围评估

**预计交付：** 代码质量分析 + 依赖追踪工具。

### Phase 5: 远程连接与双模式

**难度：★★★★★ | 预估工时：6h**

> 实现远程云端连接，以及本地/远程双模式自动切换。

核心任务：
- 云端服务认证
- 远程数据集查询
- 本地与远程模式自动路由
- 远程场景下的元数据获取方案

**预计交付：** 双模式连接能力，本地和云端数据集均可查询。

## 6. 风险与对策

| 风险 | 概率 | 对策 |
|------|:---:|------|
| PBI Desktop 版本更新导致接口变化 | 低 | 使用官方标准接口，微软保持向后兼容 |
| Power Query 修改不可行 | 中 | 优先实现读取，修改能力作为二期目标 |
| 官方 MCP 功能完善后替代 | 中 | 差异化：Python 环境、零认证、离线可用 |
| 大型模型查询超时 | 中 | 利用引擎内存计算，复杂查询建议在 Desktop 中执行 |
| 远程连接认证复杂 | 高 | 优先使用标准 REST 接口，高级协议作为长期研究课题 |
